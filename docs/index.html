Line-length formatter

The block becomes a pyramid.

Pyramid Sort reorders a block by trimmed line length. Imports, JSX attributes, types, objects, and CSS. The same order on save, in the CLI, and in whatever agent just edited the file.

Install the extension More examples

Why

Order you can see.

Alphabetical sort hides the long line in the middle. Pyramid Sort puts weight where your eye already goes: short first, then the line that needs the room.

01
You scan the short line first.

A prop named ref should not sit under a class string the width of the editor. Length is the sort key, so the silhouette matches the reading order.

02
The argument about “import style” ends.

Two people, or a person and an agent, stop rearranging the same block. External packages stay above local paths. A blank line is a wall between groups.

03
Spreads do not move.

{...props} stays where it was written. Named attributes sort on each side of it, so override order does not change because a formatter got clever.

04
Unsafe JSX is left alone.

If an opening tag is not safe to rewrite — a nested element, a callback with a > — Pyramid Sort does not touch it.

What

Five kinds of block. One rule.

Each category has its own direction, including auto: a short opener sorts the body ascending, a long opener sorts it descending, so the pyramid follows the line above it.

Imports

Packages, then your code.

Length inside each group. Aliases from tsconfig, jsconfig, and Vite count as local. Multi-line imports can reflow. Single-line imports stay one line.

Attributes

The tag becomes a wedge.

Multiline JSX and HTML. Spreads are boundaries. A group that contains a spread can be skipped entirely.

Types

Members, not the name.

Bodies of type, interface, and enum. Blank lines keep separate groups.

Objects

Literals with a spine.

const objects and return {. Nested objects are opt-in, and they stay intact.

CSS

Declarations, not selectors.

Rules in CSS, SCSS, and Less. Nested rules stay put. @keyframes steps are not reshuffled as blocks.

Force sort

Any selection.

No parser. Selected lines, any language, ordered by length. Blank lines can still split groups.

How

One file decides.

.pyramidsort is JSON. The editor and the CLI read the nearest one. On-save toggles in that file are what a bare npx pyramid-sort will run.

Install

The VS Code extension, which Cursor loads too, or the pyramid-sort package on npm.

Write the config

Command Pyramid Sort: Generate Config File dumps your editor settings into .pyramidsort.

Save, or hand it the paths

On save in the editor. Or npx pyramid-sort a.tsx b.tsx after an agent edits those files.

Types, objects, and CSS stay off until you turn on sortTypesOnSave, sortObjectsOnSave, or sortCssOnSave. Imports and attributes are on by default. diagnostics only controls the Problems tab. It does not turn sorting on.

Put it in the editor. Or in the turn.

Marketplace id INVEON-Development.pyramid-sort. The CLI sorts every path you pass, and it reads .pyramidsort beside each file.
