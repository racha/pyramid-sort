AI workflow

The agent edits. The CLI finishes the shape.

Do not ask the model to sort by length. It will improvise. Point it at npx pyramid-sort and let .pyramidsort decide which categories run.

The one command

Pass every path from the turn. The CLI sorts them in order, reads config next to each file, and prints the paths that changed when there is more than one.

npx pyramid-sort src/components/form/fields/InputField.tsx src/pages/dashboard/test.tsx

No --imports-only. No second call for attributes. Those flags override the config. Use them only when you want a single category. --all-categories sorts every category and ignores the on-save toggles.

A missing path exits non-zero and names the path. Nothing is written.

What .pyramidsort turns on

Generate it from the editor with Pyramid Sort: Generate Config File. The keys that matter for the CLI are the on-save flags:

{
  "sortImportsOnSave": true,
  "sortAttributesOnSave": true,
  "sortTypesOnSave": false,
  "sortObjectsOnSave": false,
  "sortCssOnSave": false
}

diagnostics.types and the other diagnostic flags only affect the Problems tab. They do not enable sorting. Direction, grouping, and extensions live in the same file.

Cursor stop hook

On-save does not see every tool edit. Record the paths during the turn, then sort them once when the agent stops. The stop hook’s own stdout must stay {}. Send the CLI’s output to stderr.

.cursor/hooks.json

{
  "version": 1,
  "hooks": {
    "afterFileEdit": [{ "command": ".cursor/hooks/record-js-edit.sh" }],
    "afterTabFileEdit": [{ "command": ".cursor/hooks/record-js-edit.sh" }],
    "stop": [{ "command": ".cursor/hooks/pyramid-sort-on-stop.sh", "timeout": 120 }]
  }
}

.cursor/hooks/pyramid-sort-on-stop.sh

#!/usr/bin/env bash
set -euo pipefail
root="${CURSOR_PROJECT_DIR:-$PWD}"
pending_dir="${TMPDIR:-/tmp}/cursor-pyramid-sort"
pending="$pending_dir/$(printf '%s' "$root" | shasum | awk '{print $1}').txt"
if [[ -s "$pending" ]]; then
  files=()
  while IFS= read -r file; do
    [[ -f "$file" ]] || continue
    case "$file" in
      *.js|*.jsx|*.ts|*.tsx) files+=("$file") ;;
    esac
  done < <(sort -u "$pending")
  rm -f "$pending"
  if [[ ${#files[@]} -gt 0 ]]; then
    npx --yes pyramid-sort "${files[@]}" >&2
  fi
fi
printf '%s\n' '{}'
sleep 0.05

The recorder, record-js-edit.sh, appends each edited .js, .jsx, .ts, or .tsx path to that pending file. The list is removed before npx runs, so a failed CLI run drops the unsorted paths. Keep the script, and change only the npx line if you already have the two-call version (--imports-only then --attributes-only).

Shell edits are invisible to afterFileEdit. The Cursor rule covers those. Pyramid Sort: Setup AI Hook & Cursor Rules writes .cursor/rules/pyramid-sort.mdc only when that file is missing, so an existing rule has to be edited by hand:

npx pyramid-sort src/components/form/fields/InputField.tsx src/pages/dashboard/test.tsx

VS Code agents and Antigravity

Copilot, Antigravity in VS Code, and the Antigravity IDE agent get the same instruction: after editing files, run one npx pyramid-sort with those paths. Do not loop one file at a time. Do not reimplement the sort in the model.

Whole tree, when you mean the whole tree:

npx pyramid-sort . --sort-all
npx pyramid-sort . --scan

--scan prints a Markdown report and exits 1 when it finds unsorted blocks. It does not write.
